## Judgment

Use **Candidate A as the base**. Its mapped `RowEntries<S>` witness is the best fit for the explicit requirement to preserve weakening by independent keys. Unlike whole-row invariance, it lets a pure computation be annotated with a requirement and lets a computation retain its current contract while acquiring a distinct requirement. It also avoids a caller-managed `widen` operation, which would create a new route to accidentally alter existing entries.

Graft from B the explicit negative contract matrix and the rule that checked APIs derive identity and answer contract from one validated declaration wherever possible. In particular, share one admissibility predicate across `effect.handle`, `.handler`, `.intercept`, standalone `makeHandler`, and fixed `Requirement` entries. Keep public operation identity string-based for this repair; caller-owned symbols solve collision identity but are an outsized migration and do not by themselves solve dependent answer protocols or replacement escape hatches.

Reject B's whole-row invariant witness as the base because it fails the independent weakening requirement as written. Also reject B's mandatory caller-minted symbol IDs for this cleanup: it is a coherent larger redesign, but changes every effect/tag declaration and the built-in row ecosystem while A addresses the demonstrated holes with substantially less surface churn. Do not graft B's nominal descriptor API piecemeal; a partial string/symbol split creates two operation identity systems and duplicate checked/unchecked paths.

## Necessary constraints on Candidate A before implementation

1. **Keep the invariant witness on each complete entry**, with the row itself contravariant. Do not replace it with whole-row invariance, answer-only invariance, or `Required`-based payload extraction. Ensure `KyootImpl`/recursive iterator and generic adapters still honor the declared variance rather than relying on casts that erase rows.
2. **Validate literal identity at every checked removal boundary.** `effect`'s declaration key and raw `makeHandler` dispatch must reject unions, `never`, broad string, and open template-string types such as `` `var/${string}` `` and `` `${number}` ``. Check branded open strings and explicit generic arguments as well. `Record<K, unknown>` is a promising open-key detector in the isolated probe, but its inference behavior must be proved through the real API. Keep any broad runtime dispatch in a private trusted path.
3. **Prevent effect creation from preloading an overlapping C row.** `Performed` currently intersects its requirement with C. Reject same-key overlap and broad index C at the checked factory boundary; checking only during handler application leaves the unsafe intersection constructible. Preserve independent C keys and `Resume.with` dependencies.
4. **Make fixed and dependent entries disjoint.** Give Var a dependent discriminator/family brand, and do not leave `any` in a public fixed-compatible position. Audit Async, Sync, Resource, Emit and other raw/dependent rows individually. A marker alone is insufficient: each family's public `run`/`handle`/`intercept` route must either preserve its operation-to-answer relation or be outside the checked replacement surface. In particular, current `Sync.handle` yields `Resume<unknown>` and Var's `intercept` accepts arbitrary replacement programs, so those cannot inherit safety merely from branding.
5. **Close all package-visible checked routes.** `checkedMakeHandler` currently is exported as `makeHandler`; effect-level handle/handler use `unsafeMakeHandler`, and `makeIntercept` is exported as `unsafeMakeIntercept`. Keep deliberate unsafe names only as explicit unsafe facilities, but ensure ordinary checked declarations/interceptors cannot turn a hidden dependent answer into arbitrary `resume`. Do not leave `core.ts` internal imports as a supported external route if package subpath exports expose them.
6. **Pick and prove a same-key union policy.** Either require the row entry to be exactly the declared `Requirement`, or accept only unions proven entirely fixed while ensuring payload callback coverage and resume answers satisfy every member. The latter is more complex; default to exact single contracts unless existing valid same-key use requires unions. `AnswerOf` must not fall back to `any` for raw, unknown, dependent, or malformed rows.

## Proof gates for the implementation owner

The isolated type probe is useful, but the decisive artifacts are package-export compile fixtures for the old intersection and union reproducers; positive fixtures for pure-to-effect weakening and adding distinct requirements through assignment, arguments, return, and `pipe`; explicit generic and open-template key rejection; effect/C overlap rejection; and fixed-versus-Var/Sync/Resource rejection through every checked entrypoint. Then compile built-in Var/Env/Sync/Async/Resource use and the monorepo. Treat runtime test results as a separate check that marker/signature edits did not alter interpretation. These are gates, not claims that either design has already passed them.
